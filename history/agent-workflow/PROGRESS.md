## Обязательный цикл для каждого файла

### 1. Refresh
Перед каждым новым файлом перечитать:
- `HANDOFF.md`
- `PROGRESS.md`
- `ERRORS.md`
- `IMPROVEMENTS.md`
- `CHRONOLOGY.md`
- `AGENTIC_DEVELOPMENT.md`

После каждых 3 файлов или при противоречии дополнительно освежить актуальные `STATE.md`, `TASKS.md` и relevant branches проекта.

### 2. Register
До глубокого разбора добавить файл в таблицу ниже со статусом `IN_PROGRESS`.

### 3. Analyze
Использовать `CHAT_REVIEW_TEMPLATE.md`. Искать замечания пользователя, ошибки агента, улучшения workflow, технические этапы и изменения распределения ответственности человек ↔ агент.

### 4. Consolidate
Не плодить дубли. Повторные эпизоды добавлять к существующим ID и повышать уверенность/статус.

### 5. Update
Обновить все затронутые журналы и строку файла в таблице.

### 6. Handoff
Перед завершением обработки файла убедиться, что следующий агент сможет продолжить только по содержимому этой директории и текущему Git-состоянию.

## Контроль дедупликации

После каждого файла отдельно проверить:
- не создан ли новый ID для уже существующей причины;
- не записано ли улучшение второй раз под другим названием;
- не принят ли современный факт из `STATE.md` за историческое доказательство;
- не сделан ли вывод об отсутствии tool-call только потому, что он не виден в выгрузке;
- не потеряно ли раннее ошибочное убеждение, если позднее оно было исправлено — для истории важен сам переход.

## Финальный этап аудита

После обработки всех предоставленных файлов:
1. перечитать весь audit corpus целиком;
2. сверить его с живым состоянием веток, которое могло измениться из-за параллельной работы агентов;
3. консолидировать ошибки и улучшения;
4. подготовить отдельные предложения по изменению базового промпта;
5. подготовить связный отчёт об эволюции технического проекта и агентной разработки;
6. ничего не переносить в основную документацию без отдельного решения пользователя.
