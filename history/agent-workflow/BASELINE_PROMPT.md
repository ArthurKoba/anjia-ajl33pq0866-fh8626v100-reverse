# Базовый рабочий промпт — исходная версия перед аудитом чатов

Этот файл фиксирует исходные пользовательские правила, относительно которых анализируются старые диалоги. Он является снимком до внесения выводов из исторического аудита.

1. Команды отправлять одним копируемым блоком. Если нужно выполнить несколько связанных команд, помещать их в один code block. Каждая команда должна быть на отдельной строке. Не склеивать команды через `&&`, `;` и длинные однострочные конструкции без необходимости. Не отправлять по одному code block на каждую команду.

2. Работать пошагово. Если результат команды влияет на следующий шаг, не отправлять сразу длинную цепочку дальнейших команд. Режим: дать небольшой логически связанный блок; пользователь выполняет его и присылает вывод; агент анализирует результат; после этого даёт следующий блок. Не перекладывать ветвление на пользователя в формате «если A — делай B, если C — делай D». Решение по результатам команд принимает агент после получения вывода.

3. Перед блоком команд переходить в нужную директорию. Если команды зависят от текущего каталога, первой командой указывать `cd /нужная/директория`. Не рассчитывать, что терминал всё ещё находится в прежнем каталоге.

4. Для передачи нескольких файлов предпочитать архив. Если нужно передать несколько файлов, патчей, тестов или конфигов, удобнее собрать их в один архив и работать уже с ним. Если путь загрузки неизвестен, сначала уточнить, куда файл скачался или какой путь используется. После этого давать команды с фактическим путём.

5. Не усложнять применение изменений. Если можно передать готовые файлы, архив, patch или overlay, предпочитать это ручному созданию большого количества файлов. Не использовать Python только ради простого копирования, распаковки или применения патча, если это нормально делается обычными shell-инструментами.

6. Не делать лишних проверок. Работать по принципу try: сначала пробовать разумный следующий шаг, а если что-то пошло не так — разбирать фактическую ошибку. Не дублировать проверки, контрольные суммы, статусы и сверки без причины. Дополнительные проверки уместны перед важным финальным этапом или продом, но не на каждом шаге.

7. Nginx обычно работает через Docker Compose. Типичная структура: `/srv/nginx`, `/srv/nginx/configs`, `/srv/nginx/logs`. Docker Compose обычно запускается из `/srv/nginx`. Если создаётся новый `docker-compose.yaml`, не добавлять верхнеуровневое поле `version:`.

8. Не отправлять лишние будущие сценарии. Если сейчас нужен только один следующий шаг, дать только его. Не расписывать заранее несколько веток развития событий. Главный принцип: команды → вывод пользователя → анализ агента → следующие команды.

9. Когда предлагаются команды, никогда не разделять их построчно через символ `\\`.

10. При работе с архивами всегда распаковывать файлы в рабочее пространство и работать с ними напрямую. Постоянно использовать средства распаковки для извлечения файлов — антипаттерн. Архивы используются только для получения данных от пользователя и передачи ему архивов. Во всех остальных случаях работа должна происходить с заведомо распакованными файлами.
