# Улучшения workflow и best practices

Назначение: фиксировать изменения, которые реально уменьшали ручную работу, число ошибок, количество итераций, потерю контекста или стоимость передачи данных между пользователем и агентами.

## Формат записи

Для каждого улучшения:
- ID и статус;
- прежний workflow и его проблема;
- новый workflow;
- почему он оказался лучше;
- ограничения/ловушки;
- чаты, где переход возник или подтвердился;
- возможный кандидат на базовое правило.

## Исходные этапы для проверки по чатам

### I-001 — Ручные браузерные вставки → workspace и архивы
Статус: `BOOTSTRAP`.

Гипотеза: вместо большого количества ручных вставок и создания файлов начали передавать подготовленные наборы файлов/архивы и работать с ними как с единым состоянием задачи.

Нужно по чатам восстановить точный момент перехода, причину и реальные преимущества.

### I-002 — Workspace → Google Drive как постоянное внешнее хранилище
Статус: `BOOTSTRAP`.

Гипотеза: локальное/временное workspace-состояние оказалось недостаточно устойчивым, после чего Google Drive стал использоваться для долговременного хранения и синхронизации тяжёлых/важных материалов.

### I-003 — Google Drive → GitHub как authority для исходников и инженерного состояния
Статус: `BOOTSTRAP`.

Гипотеза: GitHub добавил версионирование, историю изменений, ветки, handoff между агентами и более устойчивую совместную разработку.

Нужно отделить то, что стало храниться в Git, от того, что осталось на Drive как тяжёлое evidence.

### I-004 — Прямой SCP/SSH workflow для оперативной передачи на target/host
Статус: `BOOTSTRAP`.

Гипотеза: часть обмена через промежуточные хранилища стала заменяться прямой передачей файлов, когда это быстрее и надёжнее. Отдельно проверить обязательные флаги и типичные ошибки.

### I-005 — Передача значений через env для устойчивых копируемых блоков
Статус: `BOOTSTRAP`.

Гипотеза: использование переменных окружения стало способом избежать проблем, когда терминал/консоль «съедала» или искажала значения при прямой вставке.

### I-006 — Архив только как транспорт, распакованные файлы как рабочее состояние
Статус: `BOOTSTRAP`.

Гипотеза: отказ от постоянного чтения/извлечения данных из архива упростил дальнейшую работу и снизил количество лишних операций.
